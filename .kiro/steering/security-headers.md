# Security Headers & API Hardening

## Required HTTP Response Headers

All responses from the backend MUST include these headers:

```
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
X-XSS-Protection: 0
Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=(), geolocation=(), interest-cohort=()
Cache-Control: no-store, no-cache, must-revalidate
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'
```

## API Hardening Rules

### Request Validation
- Content-Type MUST be `application/json` for all POST/PATCH endpoints
- Reject requests with unexpected Content-Type (return 415 Unsupported Media Type)
- Maximum request body size: 64KB (return 413 Payload Too Large)
- Request timeout: 30 seconds per request
- Pydantic models MUST use `model_config = {"extra": "forbid"}` to reject unknown fields

### Response Sanitization
- NEVER include stack traces in production error responses
- NEVER include internal server paths in error messages
- Return generic error format: `{"detail": "human-readable message"}`
- Remove `server` header from responses (don't reveal uvicorn version)

### Rate Limiting
- Admin endpoints: 100 requests per 60 seconds (global, existing)
- Submission endpoint: 10 submissions per hour per session (new)
- Status check: 60 requests per minute per session (new)
- Auth endpoint: 5 attempts per 15 minutes (lockout, new)

### CORS Configuration
- Production: exact origin match only (no wildcards)
- allow_credentials: False (no cookies for anonymous submissions)
- allow_methods: only GET, POST, PATCH, DELETE (explicit list)
- allow_headers: only Content-Type, Authorization

### Idempotency
- Submit endpoint accepts optional `X-Idempotency-Key` header
- If duplicate key received within 5 minutes, return cached response (no duplicate submission)
- Key format: UUID v4 generated by frontend

## Kill Switch / Maintenance Mode

### Environment Variables
```
SPILL_MAINTENANCE=false              # Full maintenance mode (503 all endpoints except /health)
SPILL_SUBMISSIONS_ENABLED=true       # Toggle submissions only
```

### Maintenance Mode Behavior
- All endpoints return 503 with Retry-After header
- Exception: /health returns {"status": "maintenance"} with 200
- Frontend detects 503 and shows maintenance page

### Emergency Lockdown (admin-triggered)
- POST /api/v1/admin/emergency/lockdown — enables maintenance mode at runtime
- Requires admin auth
- Persists until manually disabled or env var override on restart
